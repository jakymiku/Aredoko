# 仕様たたき台 v0.1

## 確定した方向
- 名称: Aredoko。Windows PCでGUIから起動・操作する。
- 複数の指定フォルダとサブフォルダを対象にする。除外指定を設ける。
- 曖昧検索、関連ファイル表示、仮想の棚・タグ・お気に入りを統合する。
- 元ファイルの配置は変更しない。移動・変換後も整理情報を引き継げるようにする。
- 数万ファイル以上・1TB以上を想定。PC: i7-13700K / RAM32GB / RTX4070Ti 12GB。
- 本は画像フォルダ・ZIP・CBZが混在、PDFは少数。画像・動画・音楽・素材も扱う。
- Komgaは読書時に起動するため、アプリの検索と管理はKomgaから独立させる。
- OSS・インストール済みアプリの曖昧検索は別企画とする。

## 提案仕様（実装前に調整可能）
### ライブラリ
登録単位に本中心・素材中心・混在の設定を持つ。画像フォルダやZIPを1冊として扱うか個別素材として扱うか変更できる。
ファイル実体の場所と論理的な作品IDを分離し、同一内容の複数保存先も保持する。
オフラインドライブは未接続扱いとし、タグ・プレビュー・検索データを維持する。
移動は内容一致などで確認する。フォルダ→CBZ変換など曖昧な対応は候補提示と手動差し替えで扱う。
### 検索・整理
ファイル名・タグ・作者などの文字検索と意味検索を併用する。
本のページやメディア区間で検索し、結果は作品単位に集約する。
類似度は正解率として表示しない。AIタグ候補と手動確定タグを区別し、再解析で手動編集を上書きしない。
棚は複数所属可能。お気に入り、未確認、最近追加を用意する。
### 閲覧
表紙一覧、詳細、関連ファイル、読書ビューア、タグ編集。
読書は左右開き・見開き・拡大・読書位置保存。音楽と動画は形式対応を検証し、非対応は外部アプリで開く。
### Komga
稼働時に既存メタデータを取得し、未起動時はキャッシュ表示。対応済み作品をKomgaで開く。
初期は読み取り連携。タグの書き戻し・読書位置の同期は未確定。
### 解析
登録→プレビュー生成→内容解析の段階処理。途中でも一覧と整理を使える。
永続キュー、中断再開、追加変更の差分解析、優先解析、軽量モード、キャッシュ上限を設ける。
EmbeddingGemma 2を候補とし実データで精度評価する。Layaは分類の候補で、採用は未確定。
ローカル処理を基本とし、モデル取得とKomga接続以外の外部送信を必要としない構成を目指す。
