# GUI比較計画

## 候補
A: Tauri + React + Python。B: WinUI 3 + C# + Python。
共通のデータ仕様と同じ縮小画像を使い、AIなしのGUI比較とAI込みの全体評価を分離する。

## 比較画面
1. 5万件の一覧: 仮想化、サムネイル、検索、種類フィルタ、複数選択。
2. 読書: 画像フォルダ・ZIP・CBZ、前後ページ、見開き、拡大。
3. タグ: 単体・一括編集と永続化。

## 公平な条件
Releaseビルド、同一PC・表示サイズ・画像解像度・先読み枚数・キャッシュ上限で比較。
初回起動とキャッシュ済み起動を分け、同じ操作を3回測る。
ウィンドウ本体だけでなくWebView2やPythonを含めた関連プロセスを測る。
Private BytesとWorking Setを別に記録し、共有メモリの二重計上に注意する。GPUメモリも別項目にする。

## シナリオ
起動→一覧スクロール→検索→本を開く→50ページ送る→タグ編集→閉じる、を10回繰り返す。
起動直後、スクロール後、読書中、閉じた後、トレイ格納後、復帰後で測定する。
起動時間、表示待ち時間、スクロール停止、メモリの増加傾向、復帰速度を記録する。
使用データ・コミット・ランタイムのバージョンを結果に添える。

## 判定
メモリだけでなく、操作感、アクセシビリティ、保守性、配布の手間も比較する。
現時点で性能測定結果はない。GUI方式は未決定。

## 必要な準備
.NET SDK / Windows App SDK / Windows向けビルドツール、およびRust / Tauriビルド環境を確認・導入する。
架空メタデータだけでは画像展開の負荷を測れないため、共通サムネイルと使用許可済み実ファイルを追加する。
