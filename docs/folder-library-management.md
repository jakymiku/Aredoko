## 1. 目的と着手タイミング

登録ルートが増えると左ナビのフォルダ列挙が煩雑になるため、左側は「登録フォルダ」という入口にまとめる。メインビューにリスト／グリッドの登録フォルダ一覧を設け、そこから閲覧・検索対象選択・設定変更・登録解除を行う。WinUI 3ネイティブ、コンパクトなナビ、広い中央一覧、右詳細パネルを維持する。

**OpenCodeが現在開発中。実装担当は進行中の作業・未コミット変更・最新remoteを先に確認する。実行中のテストや編集中のコードを中断・上書きして本件へ切り替えない。** 現行タスクを安全に区切った後、次の操作性改善の縦切りとして本件を選ぶ。現在進んだP0/P1等を古いhandoffの状態へ戻さず、既存の有限な評価ルール・CI節約も維持する。今回の文書担当はユーザーPCの未コミット変更やOpenCodeのローカル進捗を観測できていない。

## 2. 既存実装として確認できたもの

確認基準は文書作成前のremote `4c98bafa3e2703fc6f0355873104bc8e89cbc3b2`。実装開始時は必ず更新を再確認する。

- `src/Aredoko.WinUI/MainPage.xaml` と `MainPage.xaml.cs`：左ナビへ登録中／解除済みルートを動的追加。通常の検索フォルダ選択は単一root。フォルダ管理はContentDialog。
- 登録時の項目は「タグ」ではなく **初期棚（default_shelf）**。新しく見つかったファイルへ棚を設定する。初期棚保存、除外更新、スキャン／再開／取消、登録解除／再登録の入口が存在する。
- `POST /api/library/roots/shelf` の `fill_unset` による既存の棚未設定ファイルへの適用がある。現UIには「個別に解除した棚を含む」と明記されており、この違いを新UIでも隠さない。
- AIのscopeには複数 `root_ids` が存在する。一方、通常検索・AI・類似検索を同一の複数選択UIで扱えることは未実証。既存のscope／検索rootの積み合わせ・API契約を読んでから拡張する。
- 登録解除は元ファイルと保存済みタグ・棚を保持し、再登録時に復元する既存動作を維持する。

初期棚を新しいタグ機能として作り直さない。フォルダ共通タグや各作品へのタグ一括付与は本件の初期範囲に含めない。

## 3. 画面と操作

| 場所・操作 | 期待動作 |
| --- | --- |
| 左ナビの「登録フォルダ」 | メインに登録フォルダ一覧。登録数だけナビ項目を増やさない |
| 一覧の検索欄 | 登録フォルダの名前・パスを絞り込む。作品検索とは区別 |
| リスト／グリッド切替 | 同じフォルダ集合と選択状態を保つ |
| フォルダ名または「中を見る」 | 対象root配下の作品・素材一覧へ移動。サブフォルダを含む |
| 行／カードのチェックボックス | 複数root選択。チェック操作でフォルダ内へ遷移しない |
| 選択時の操作バー | 「選択したNフォルダを検索」「設定」「登録解除」。適用範囲を明示 |
| フォルダの「設定」／右クリック | 右詳細パネルで初期棚・除外・スキャン・登録解除等を編集。狭幅は既存方針のドロワー等 |
| 作品検索画面 | 検索欄付近に対象名と件数、変更／全登録フォルダへの明示切替を表示 |
| 検索対象の「変更」／フォルダ一覧への復帰 | フォルダの選択・絞り込み・表示形式を復元。作品側の検索条件も勝手に消さない |

一覧にはフォルダ名、区別可能な短縮パス、登録中／解除済み、接続状態を表示。件数や最終スキャン状態は取得可能なデータで表示し、件数表示のために新たな私物スキャンを始めない。フルパスは詳細／ツールチップで確認できる。解除済みルートは同画面のフィルター／区画にまとめ、再登録の既存導線を失わせない。

フォルダを開く操作と複数選択は分離する。設定ボタン／右クリックならフォルダ内へ移動せず編集できる。単一クリック・チェック・キーボード操作のイベント競合を避ける。

初期範囲は登録root単位の検索。登録root配下の任意のサブフォルダだけを選んで検索する機能は、必要なパス境界契約を別途設計し、実装済みとしない。

## 4. 検索対象の契約

1. 通常文字検索・関連語・AI文章／画像／混合・アイテム起点類似検索で、選択root集合を同じ意味で扱う。複数選択は **OR（選択したフォルダの和集合）**。種類・棚・お気に入り等の他フィルターとはAND。
2. 全登録フォルダという明示状態、選択したroot集合、未選択を区別する。チェック0件では「選択したフォルダを検索」を無効化する。空配列や削除済みID、未接続を無指定へ変換して全件検索へ広げない。
3. 選択後に登録解除されたrootは対象の見直しを案内する。未接続rootは状態を示し、利用可能性に関する既存契約を維持する。残りの対象だけで継続できる場合も範囲変更を明示し、無断で全rootへ置換しない。
4. 検索用の選択を変更しただけで、保存済みのAI索引対象scopeを書き換えたり、索引作成・モデルロードを始めたりしない。既存AI scopeと検索root集合の関係を明文化し、既存の明示scopeより検索範囲を広げない。積集合で狭くなる場合は実効対象と理由を表示する。拡張が必要ならユーザー操作で対象を変更する。
5. AIの未索引・部分索引・古いrevision・モデルprofile、検索対象1万件枠等の制約は保持し、フォルダ選択で制限を黙って回避しない。通常検索とAIの件数差は説明可能にする。
6. 単一rootの旧呼出しは互換保持。root IDの検証、重複・不正値・登録状態、認証、ページング、自己除外、除外ルールをAPI側でも保証する。新しい複数root契約の上限は既存の最大256件と整合させる。GUI上でフィルターしただけをAPI対応と呼ばない。
7. 範囲変更時はページを適切に初期化し、遅い旧応答を排除する。検索から戻る・類似検索から元検索へ戻る場合はquery／root集合／他フィルター／view／page／focusを復元する。未保存の作品編集には既存の保存／破棄／取消確認を維持する。

## 5. 除外・登録解除の名前と意味

| 表示名 | 影響 |
| --- | --- |
| 今回の検索対象から外す | 今回の検索用root集合だけを変更 |
| 索引対象から除外／除外ルール | 指定した配下等を継続的な索引・検索対象から除外。既存ルール・反映タイミングを明示 |
| 登録解除 | Aredokoの登録を解除。元ファイル、手動整理情報を保持。再登録を可能にする |

「削除」の曖昧なボタンで実ファイル削除を実装しない。検索対象から外すことを恒久除外や登録解除と混同しない。複数解除は対象名・件数を示して明示実行し、部分成功／失敗時は各結果を報告する。無断で別のフォルダを処理しない。

## 6. 初期棚・設定の編集

### 単一フォルダ

- 右詳細パネルで「初期棚」「除外ルール」とスキャン状態を確認・編集。初期棚は既存棚選択、新しい棚作成、棚なしを提供する。
- 初期棚変更の既定は今後新しく見つかるファイルへの適用。既存の作品にユーザーが個別設定した棚は上書きしない。
- 「既存の棚未設定ファイルにも適用」は明示オプション。現APIでは個別解除した棚も対象になり得るため、その意味と適用件数を表示する。対象件数の事前取得が未実装なら推測せず、完了件数を示す。
- 既存ファイルへの適用・除外反映のタイミングはAPI実態に合わせる。自動で全フォルダを再スキャンしない。
- タグ、棚、お気に入り、確認状態、読書位置は保全。設定の未保存変更も移動時に保存／破棄／取消を扱う。

### 複数フォルダ

- 同じ値ならその値、異なる値なら「複数の設定値」を表示する。「複数の設定値」「変更しない」「棚なし（明示的な解除）」を内部状態でも区別する。
- **ユーザーが変更した項目だけを保存する。** パネルを開いただけで各rootの初期棚や除外を空にしない。
- 最初の一括編集は初期棚を中心とする。除外ルールの一括置換は初期必須にせず、後続で実装する場合は追加／置換・適用対象を明示し、既存ルールを黙って消さない。
- 保存失敗時は成功／失敗したrootを識別し、未保存入力を残す。既存単一root APIを順次利用する場合は全体成功と偽らず、失敗分だけ再試行できるようにする。独立した既存編集を全件再適用しない。
- 一括設定とスキャン／AI索引の競合は既存busyルールに合わせる。設定保存を契機に重い解析を始めない。

## 7. 小さく実装する順序

1. **登録フォルダ画面＋単一設定**：左の列挙をまとめる。リスト／グリッド、名前／パス絞り込み、フォルダ内閲覧、右詳細で既存の初期棚・除外・スキャン・解除／復元を利用可能にする。
2. **複数選択検索**：通常検索API／Coreから必要な複数root契約を追加し、AI・類似検索のscopeと整合させてGUIへ接続。選択範囲表示と復帰を含める。既存AI複数scopeを作り直さない。
3. **一括管理**：初期棚の変更項目だけ保存、棚未設定への明示適用、複数登録解除と部分失敗表示。各段階で既存機能を使える状態に保つ。

フォルダ一覧のリスト／グリッドと検索は初期範囲。**検索範囲に名前を付けて保存、ピン留めした範囲だけ左ナビへ表示**する機能は後続。フォルダの表紙コラージュ、全体デザイン刷新、階層ツリー、大量サムネイル生成も今回必須にしない。

## 8. 受け入れ条件と検証

生成した複数root／同名末尾フォルダ／解除済みroot／未接続状態のfixtureを使う。私物データの無断登録・走査・外部転送は行わない。

- 登録数が増えても左ナビに全rootが並ばない。リスト／グリッド、名前／パス絞り込み、選択、単一フォルダ内閲覧、設定への導線が成立する。
- A/B/CのうちA+Bを選ぶと通常・AI・類似検索の対象が同じ選択範囲となり、Cは混ざらない。既存AI scopeが狭い場合はその制約を明示。種類・棚・お気に入り・除外・自己除外・ページングも維持。
- 0選択・解除／不正root・未接続・選択変更中の遅延応答で検索対象が全体へ拡大しない。検索／類似検索から戻ると条件と選択が復元される。
- 初期棚の今後分／既存未設定への明示適用、個別棚保全、複数値／変更しない／棚なし、部分失敗と未保存確認を検証する。再起動後も保存値が残る。
- 登録解除と再登録で手動タグ・棚等を保全。元ファイルのbytes／mtimeが変わらない。
- 変更に対応するPython／Coreテスト、Windows Release、WinUI実操作を実施。キーボードでチェック・設定・検索、狭幅、Light/Dark、focus復帰を確認する。Windowsがない環境の成功をGUI合格にしない。
- CIはAGENTSのmanual-only／資源制約を守る。文書のみの今回にCIや製品テストを回さない。実装時も必要な局所テストを選び、同じ評価を無目的に反復しない。

各縦切りの完了／未検証をhandoffへ記録して次へ進む。既に他AIが実装していた場合は作り直さず差分と残課題のみ扱う。
