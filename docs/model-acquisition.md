# 配布版のモデル導入・進捗・手動配置（2026-10-21 ユーザー指定）

## 決定と現在の状態

配布版の「設定 → AI検索の準備」で、モデルごとに以下の3経路を用意する。現在の「モデルフォルダがありません。自動ダウンロードは行いません。」だけで止まる導線を置き換え、既存モデルを再取得せず使えるようにする。**今回確定したのは仕様で、GUI downloader/フォルダ指定はまだ未実装**。新しいmodel/依存の実取得やGPU/GUI検証は実施していない。

1. **アプリでダウンロード**：選択した対応モデルをアプリが取得・検証・配置する。保存先、必要容量、固定版、配布元/ライセンスを開始前に確認できる。ユーザーの開始操作で取得し、起動/検索/モデル選択だけで勝手に大容量downloadしない。自動取得設定を追加する場合も明示opt-in、既定offとする。
2. **配布元から手動ダウンロード**：公式ページと必要ファイル/版/配置先を表示し、ユーザーがブラウザ等で取得する。その後は既存フォルダを選択して検証する。外部ブラウザのdownload進捗をアプリで測れない場合、測れているように表示しない。
3. **配置済みフォルダを選ぶ**：既に取得済みのローカルモデルを参照する。無断コピー/移動/削除/上書き、PC全体の探索をしない。ユーザーが自分で配置したモデルも同じ検証経路を使う。

通常UIはモデル名・準備状態と3つの導入操作、取得中の進捗だけに留め、細かい版情報/技術診断/帯域設定は必要時に開く。新しい複雑な管理画面を追加せず、既存の「AI検索の準備」に収める。EG2、WD Tagger、必要なLaya等のroleを区別し、1つを取得しただけで全AI機能の準備が完了したように表示しない。対応adapter/profileの拡張性は保持し、任意のモデルが無条件に動くとはしない。

## 速度と進捗（ユーザー訂正を優先）

**配布版のdownload速度は既定で制限なし。6MB/sを固定/既定にしない。** 必要な利用者が任意に上限を設定できるようにする。上限を有効にした場合は並列file/複数モデルの合計帯域へ適用し、各接続に同じ上限を与えて合計が超過しないようにする。従来このPCで開発取得する際の6,000,000 bytes/sという個別依頼とは別の仕様である。今回、開発用downloaderや既存venvの制限は変更していない。

- 総量が分かる場合は受信済み/総bytes、実際の%を表示。分からない場合は受信済み容量と動くindicatorを示す。速度と残り時間は測定できる範囲だけ表示し、未計測値/架空%を出さない。
- 「ダウンロード中」→「ファイルを確認中」→「利用準備完了」を分け、受信100%だけで利用可能にしない。「一時停止/再開」「中止」と通信/容量/認証/版不一致等の理由を表示する。
- 部分downloadは専用の未完領域へ保存し、同一revision/fileの一致を確認して再開。サーバーが再開非対応なら安全な再取得を案内し、別版の途中fileを混ぜない。アプリ終了時は所有downloadを停止し、次回に明示再開できるようにする。
- モデル取得中でも既存の名前/タグ検索・閲覧/整理を使えるようにする。起動進捗UIとモデル取得UIは別の仕事で、通常起動のたびにモデルdownloadを待たせない。

## モデル検証・適用と実行環境の区別

固定revision/対応adapter/必要ファイル/取得元を照合し、利用可能な信頼済みsize/hashと既存profile契約で検証する。既存の`aredoko-revision.txt`等のmarkerは出自の宣言であり、ファイルの暗号学的な完全性証明と混同しない。手動配置にmarkerがない場合、必要な版確認と不足を案内し、未知の重みへ勝手に既定revisionを書いて通さない。remote codeや取得したPython scriptを実行せず、既存のlink/祖先path guardを維持する。選択したフォルダ以外を走査しない。

全fileの確認後にモデル準備済みを公開する。取得失敗・中断でも、現在の正常なモデルと索引を上書きしない。選択の保存は既存の次回起動反映を維持し、実行中workerを勝手にhot swapしない。モデル/版/入力契約別のvector identityを守り、新しい重みは別索引、同じ重みの場所変更だけで再索引を強制しない。

Python/AI依存は製品runtimeの責任で、モデル取得ボタンにpip/ドライバー/システム設定変更を紛れ込ませない。少なくとも「モデル未配置」「必要なモデルファイル不足/版違い」「同梱AI実行環境の不備」「モデル読込失敗」「索引未作成」を区別し、次の操作を示す。モデルがあるのにroot指定が違う状態をPython未導入と一括表示しない。

## 現在のMSIX Alphaで既存モデルを使う方法

これはGUIフォルダ指定ができるまでの既存機能による手動設定。製品の完成導線ではない。

既定配置は `%LOCALAPPDATA%\Aredoko\models\embeddinggemma-2`。モデル一式を手動配置する場合、重みだけでなく設定/tokenizer等も同じexport構成で保持する。現在の既定profileに合う版情報も必要。アプリ本体のWindowsAppsや封印済み配布へ入れない。

この開発PCで準備済みの`C:\AI\Aredoko\models\embeddinggemma-2`を再利用するには、Aredokoを終了して `%LOCALAPPDATA%\Aredoko\launch-settings.json` に次を設定する。**既存JSONがある場合は既存の項目を保持してmodels_rootだけ追加/更新**する。

```json
{
  "models_root": "C:\\AI\\Aredoko\\models"
}
```

指定は個別modelフォルダでなく、その親のmodels root。デスクトップの製品用「Aredoko Alpha」リンクから次回起動すると反映する。このターンでは対象フォルダ/版markerの存在をread-only確認したのみで、個人設定やモデルは変更せず、モデルロード/GPU試験も行っていない。

## 実装順と受入

[portable-distribution.md](portable-distribution.md)のPZ2起動入口/進捗を先に進め、PZ3の配布runtime・モデル保存先契約に本仕様を組み込む。次の順で最小の導入フローを作る。

1. **配置済みフォルダ指定と診断**：保存/再起動後の反映、同じ重みの索引再利用、モデル不足とruntime不足の区別。既存資産で再downloadなしに使えることを優先。
2. **モデル導入jobとCPU検証**：既存profile/固定revision/WDのartifact hash契約を再利用し、stage→全検証→publish、取消/中断/再開、設定保存を分離。既存`tools/download-ai-model.py`/`setup_wd_tagger.py`は開発用入口のため、そのままGUIからpip付きで呼ばず分離する。
3. **GUI downloadと進捗**：既定無制限/任意上限、3経路、通常機能継続、必要な公式リンク/不足案内を接続。CPUではlocalhostの生成file/serverで破損/中断/帯域/再開を検証し、実モデル取得や実GPUの代用としない。
4. **許可後の製品受入**：用意した具体物/必要な取得範囲を提示して新規downloadやnative/GPUの最新許可を確認し、clean Windowsで手動配置と取得を確認する。旧GUI3/3上限はresetしない。

本仕様追加はモデル取得/新依存導入/GUI/GPU試験の実行許可とは分ける。R13 DOING / ALPHA未完 / R14 PARTIAL、全機能・簡潔GUI・原本/実DB/元venv保全・P0 2/2閉鎖・専用OCR保留・Actions0/main mergeなしを維持。
