# AI環境の追加と配置

ファイル名・タグの文字検索、棚、画像・動画の閲覧は、AI環境を追加する前から利用できます。

## 配置済みの環境を使う

1. 「設定」→「AI検索の準備」→「配置済みを指定」を開きます。
2. 「実行環境を選ぶ」で、Aredoko用のAI環境一式を選びます。`aredoko-ai-runtime.json` がある場所です。一般的なPythonフォルダを選ぶ操作とは異なります。
3. 「モデルのフォルダを選ぶ」で、モデル別フォルダをまとめた親フォルダを選びます。`models/embeddinggemma-2` がある場合は `models` を選びます。Aredoko向けに準備された、固定バージョンのモデル一式が必要です。
4. 検査と保存が終わったら、Aredokoを閉じて同じ入口から起動し直します。
5. 「AI検索の準備」で利用するモデルと索引の状態を確認します。新しいモデルには対応するAI索引の作成が必要です。

実行環境とモデルは別々に選択できます。「標準に戻す」は保存先の設定を戻す操作で、ファイルを削除しません。検査中は進捗を確認でき、「検査を中止」で保存前に中止できます。画面を閉じても検査は続き、同じ画面を開くと状態を確認できます。

「ファイルあり」はGPU・モデル推論の動作確認が完了したという意味ではありません。モデル不足やバージョン不一致の場合は、配置した内容と選択した親フォルダを確認してください。

## アプリからモデルをダウンロードする

1. 「設定」→「AI検索の準備」→「モデルをダウンロード」を開きます。
2. 内容検索用のEmbeddingGemma 2（文章・画像・動画・音声）（約1.53GB）、または画像タグ付け用のWD Tagger（約468MB）を選びます。
3. 容量・取得元・ライセンスを確認し、チェックを入れて「取得・再開」を押します。既定は速度無制限です。必要な場合だけ「速度制限」を展開して上限を指定できます。
4. 進捗を見ながら待ちます。「中止」した場合は途中データを残し、同じモデルの「取得・再開」で続きから取得できます。一時的な通信停止では最大2回まで自動再接続します。失敗が続く場合は、接続を確認してから再開してください。
5. 完了後「このモデルの保存先を設定する」→表示された場所を確認→「このモデルの保存先を使う」で、次回起動の保存先として指定します。開くだけでは設定は変わりません。
6. AI実行環境も配置したうえで再起動し、「AI検索の準備」で索引を作成・更新します。モデルを替えた場合、以前の索引がそのまま使えるとは限りません。

この取得は**モデルファイルのみ**です。Python/PyTorch等を含む対応AI実行環境は、現在は準備済みのAredoko用packを「配置済みを指定」から選ぶ方式です。実行環境のアプリ内取得は公開準備中です。システムPythonやGPUドライバーを自動で変更することはありません。

「配置済みを指定」→「アプリで取得・取得状況」からも同じ取得画面を開けます。モデルごとに別の保存先を指定でき、取得や保存先の選択だけで起動中のモデル・既存の索引を書き換えることはありません。

## 手動で配置する場合

上の「配置済みの環境を使う」の手順を使用できます。公式の固定版ファイル一式をモデル別フォルダへ揃え、EmbeddingGemma 2はそのフォルダの `aredoko-revision.txt` に固定revision `914f7f89142e33e77833254d9c9b90c3cef7303b` を記載します。異なる版のファイルを混ぜず、同じrevisionのモデルカードとライセンスも保管してください。アプリで取得したpackには必要な確認用ファイルとライセンスが含まれるため、通常はアプリ内取得を利用できます。
