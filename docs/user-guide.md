# Aredoko 利用ガイド (User Guide)

Aredoko（あれどこ）は、大量の画像・本（電子書籍アーカイブ）・動画・音声・デザイン素材を、名前・タグ・見た目・発話内容・音響特徴から素早く見つけ出し、整理・閲覧するためのローカルメディア管理・検索アプリケーションです。

---

## 1. 通常起動と日常利用 (Normal Startup)

### 開発環境不要の起動
- 配布パッケージ内の `start-aredoko.ps1`（または `Aredoko.cmd`）を実行することで、.NET SDK や winapp CLI 等の開発ツールをインストールすることなく起動できます。
- バックエンドプロセスはローカルループバック（`127.0.0.1:8769`）でのみ通信し、外部ネットワークへの通信（テレメトリ・更新確認・モデル通信）は一切行いません。

### オフライン通常機能の保証
- **AI環境が未導入・未セットアップの状態でも、すべての基本機能は100%オフラインで動作します**：
  - フォルダの登録・自動スキャン・差分検知
  - 表題・ファイル名・タグによる寛容な文字検索（ひらがな/カタカナ/全角半角の自動正規化、AND検索）
  - 本棚・お気に入り・未レビューによる分類と整理
  - 画像・本（ZIP/CBZ）・動画・音声の快適な内蔵ビューア閲覧
  - 本の読書進捗（ページ位置・見開き方向）の自動保存

### ユーザーデータの安全な保存先
- 登録ライブラリ情報、付与したタグ、本棚、読書履歴、設定ファイルは、既定で `%LOCALAPPDATA%\Aredoko` に永続保存されます。
- アプリケーション本体の更新やフォルダー移動、アンインストールを行っても、ユーザーが作成したカタログデータが勝手に削除されることはありません。

## 2. フォルダ登録とメディアの閲覧・整理

### フォルダの登録
1. 画面上部の「フォルダ管理」または「設定」から「フォルダを追加」を選択し、メディアが保存されているフォルダを指定します。
2. サブフォルダの走査や除外パターン（例: `*temp*`, `*.bak`）を設定可能です。
3. 登録されたフォルダの原本ファイルは**読み取り専用**として保護され、Aredokoが元ファイルを書き換えることはありません。

### 各メディアの閲覧機能
- **画像**: ホイールによるページ送り、拡大縮小、Light / Dark 各テーマでの閲覧。
- **本（ZIP / CBZ）**: 見開き（右開き・左開き）表示、単一ページ表示、サムネイル一覧、前回の読書位置からの自動再開。
- **動画（MP4 / WebM 等）**: 時間シーク、代表フレーム（最大4フレーム）の自動抽出、類似フレームへのジャンプ。
- **音声・音楽（MP3 / FLAC / WAV / Ogg / Opus 等）**: HTTP範囲ストリーミングによる即時シーク再生、音響特徴や発話内容からの頭出し再生。

## 3. AI検索とモデルのセットアップ (AI Setup)

### 明示的なセットアップ
- Aredokoは利用者の同意なくAIモデル重みをバックグラウンドで自動ダウンロードすることはありません。
- AI機能（画像の意味検索、本の中身・ページ検索、動画フレーム類似、音声発話・音響検索）を利用する場合は、付属のセットアップ手順に従ってモデルを取得・配置します。

### 推奨モデルと必要リソース
- **EmbeddingGemma 2 (2B)** (`google/embeddinggemma-2-2b`):
  - テキスト・画像・音声発話意味を共通768次元空間に埋め込むマルチモーダルモデル。
  - 推奨VRAM: 4GB以上（GPU利用時）。CPU環境でも動作可能です。
- **SmilingWolf WD Tagger** (`wd-swinv2-tagger-v3`):
  - 画像やイラストの特徴タグを自動推定するモデル。

### 索引作成の継続とメモリ管理
- 大規模ライブラリ（数万件）の索引作成は、1回あたり最大10,000件（`MAX_ITEMS=10,000`）の安全なバッチに区切られて進行します。
- 途中で「中断」した場合やアプリを終了した場合でも、作成済みのベクトルは SQLite に保存されており、次回「再開」から安全に継続できます。
- GPUメモリ（VRAM）はアイドル時に自動解放されるほか、設定画面から手動で即時解放できます。

## 4. バックアップと復元 (Backup & Recovery)

### 停止時バックアップ
- アプリを終了した状態で、付属のバックアップツールを実行します：
  ```powershell
  python tools/backup_library.py backup --catalog "%LOCALAPPDATA%\Aredoko\catalog.sqlite" --output "D:\AredokoBackup\20261019"
  ```
- SQLite WAL モードの単一ファイル整合性を確保するため、バックアップ前に `PRAGMA wal_checkpoint(TRUNCATE)` が自動実行され、破損のないスナップショットと SHA256 マニフェスト（`manifest.json`）が生成されます。

### 安全な新規ディレクトリ復元
- バックアップからデータを復旧する際は、既存の稼働中DBを誤って破壊しないよう、必ず新規ディレクトリを指定して復元します：
  ```powershell
  python tools/backup_library.py restore --bundle "D:\AredokoBackup\20261019" --output "D:\AredokoRestored"
  ```
- 復元後は自動で整合性検査（`PRAGMA integrity_check`）が実行され、安全が確認された後にアプリで使用できます。

## 5. 既知の制限事項と仕様 (Known Limits & Specs)

| 項目 | 上限・仕様 | 理由・対策 |
| --- | --- | --- |
| 索引ジョブの上限 | 1ジョブ最大 10,000 件 | メモリ枯渇・長時間ロックを防止。継続機能で全件走査可能。 |
| 全件検索の範囲 | 50,001 件以上の候補 | Keyset streaming 方式により、登録件数が5万件を超えても1万件以降を取りこぼしません。 |
| CPUベクトル順位計算 | 65,536 ベクトル p95 ≤ 10秒 | SQLite BLOB からの低オーバーヘッド内積計算により高速に処理。 |
| 音声ファイル制限 | 1ファイル最大 512 MiB / 24時間 | 巨大ファイルによるクラッシュ防止と応答性維持。 |
| 動画フレーム制限 | 1本あたり最大 4 代表フレーム | 動画全体の要約性を保ちつつ、無制限なストレージ肥大化を抑制。 |
| 専用OCRの保留 | 専用OCRエンジンは非搭載 | EmbeddingGemma 2 の視覚モデルが日本語・英語の画像内テキストを直接認識できるため、2GB超の余分なメモリ・モデル容量消費を回避しています。 |
| データベース互換性 | `PRAGMA user_version = 0` | 将来のバージョンで上位スキーマが導入された場合、古いアプリが誤って開いてデータを破壊しないようフェイルクローズ（起動拒否）します。 |
